# Lifeplan App 初期仕様

最終更新: 2026-09-01

## 1. プロダクト概要

Lifeplan App は、ユーザーが人生のお金の計画をGUIで直感的に把握できるライフプラン管理サービス。

ファイナンシャルプランナーやライフプランナーが作成するような「年表ベースの収支シミュレーション」を、専門知識がなくても個人で作成・更新できることを目指す。

対象プラットフォーム:

- Web
- iOS
- Android

## 2. プロダクトの目的

ユーザーが以下を時系列で整理し、将来の家計・資産状況を把握できるようにする。

- 収入
- 日常生活費
- 住宅関連費
- 子どもの教育費
- 自動車関連費
- 保険
- 税金・社会保険
- 大型支出
- 老後資金
- 資産・預貯金
- 投資資産
- その他のライフイベント

最終的には、「何歳のときに、どの程度のお金が必要で、その時点で資産がどれくらい残っているか」を視覚的に理解できるUIを提供する。

## 3. 基本UX

中心となるUIは「年表 / タイムライン」。

ユーザー本人および家族の年齢・ライフイベント・収入・支出・資産推移を同一時間軸上で確認できるようにする。

想定する主な可視化:

- 年ごとの収入
- 年ごとの支出
- 年ごとの収支
- 金融資産残高
- 家族それぞれの年齢
- 教育イベント
- 住宅イベント
- 大型支出イベント

詳細なUI仕様は今後決定する。

## 4. フロントエンド

### Web

- Framework: Next.js
- UI: HeroUI
- Language: TypeScript

### iOS / Android

- Expo
- React Native
- HeroUI系コンポーネントを可能な範囲で共通化
- Language: TypeScript

Web / Native 間で、ドメインロジック・型・バリデーション・APIクライアント等は可能な限り共有する。

モノレポ構成を基本候補とする。

## 5. バックエンド

Cloudflareを基本基盤とする。

候補:

- Cloudflare Workers: API
- Cloudflare D1: RDB
- Cloudflare R2: ファイル保存が必要になった場合
- Cloudflare KV: 高速参照用データが必要になった場合
- Cloudflare Queues / Cron Triggers: 非同期処理・定期処理が必要になった場合

具体的な利用サービスは要件確定後に決定する。

## 6. 認証

予定するログイン方法:

- Sign in with Apple
- Sign in with Google
- Email address

認証基盤の第一候補:

- Clerk

ClerkはNext.js / Expo双方の公式SDKが存在するため、Web・iOS・Androidを同じ認証基盤で管理する方向。

Expo側のネイティブ認証UIに依存せず、初期実装ではClerk SDKとアプリ独自UIを組み合わせることを基本候補とする。

最終採用は認証仕様確定時に決定する。

## 7. ライフプランの基本データ候補

### ユーザー

- 生年月日
- 性別（必要性を検討）
- 現在年齢
- 想定寿命
- 退職予定年齢

### 家族

- 配偶者
- 子ども
- その他扶養家族

各家族メンバーが持つ基本情報:

- 名前 / ニックネーム
- 続柄
- 生年月日
- 想定寿命

初期版では就業開始年齢・退職予定年齢・職業・勤務形態などは家族メンバー本体には持たせず、必要に応じて収入やライフイベント側で管理する。

### 収入

例:

- 給与
- 賞与
- 副業
- 配偶者収入
- 年金
- その他収入

各収入は家族メンバーに紐づく収入イベントとして管理する。

初期版で設定できる項目:

- 収入種別（給与 / 賞与 / 副業 / 年金 / その他）
- 月額または年額
- 開始年月
- 終了年月
- 年間増加率

固定額を基準とし、年間増加率を設定できる方式とする。

### 支出

例:

- 基本生活費
- 住宅費
- 教育費
- 車
- 保険
- 通信費
- 税金
- 医療費
- 娯楽
- 旅行
- その他

支出は以下の2種類に分けて管理する。

#### 継続支出

例:

- 生活費
- 住宅費
- 保険
- 通信費
- 医療費
- 娯楽費
- その他の定常支出

設定項目:

- 支出種別
- 月額または年額
- 開始年月
- 終了年月
- 年間増加率

#### 単発支出

例:

- 車購入
- 旅行
- リフォーム
- 引っ越し
- 家具・家電購入
- その他の大型支出

設定項目:

- 支出種別
- 発生年月
- 金額

### 住宅

住宅は通常支出とは分離し、専用モデルとして管理する。

初期版で扱う住宅タイプ:

#### 賃貸

設定候補:

- 家賃
- 更新費
- 開始年月
- 終了年月

#### 持ち家（住宅ローンあり）

設定候補:

- 購入価格
- 頭金
- 借入額
- 金利
- 返済期間
- 返済開始年月
- 固定資産税
- 修繕費

#### 持ち家（住宅ローンなし）

設定候補:

- 固定資産税
- 修繕費

売却・住み替え・買い替えは将来拡張とする。

### 教育

子どもごとに教育ルートを設定できる方式を検討する。

例:

- 保育園 / 幼稚園
- 公立小学校
- 私立小学校
- 公立中学校
- 私立中学校
- 公立高校
- 私立高校
- 国公立大学
- 私立大学
- 自宅通学 / 一人暮らし

教育費は、子どもごとに進学ルートを設定する。

初期版では、公立 / 私立などの標準教育費プリセットを提供し、選択した進学ルートに応じて教育費を自動入力する。

例:

- 公立小学校
- 私立小学校
- 公立中学校
- 私立中学校
- 公立高校
- 私立高校
- 国公立大学
- 私立大学

プリセットで設定された金額は、必要に応じてユーザーが個別に上書きできるようにする。

### 資産

資産はカテゴリ単位で管理する。

初期版の資産カテゴリ候補:

- 現金 / 預金
- 株式
- 投資信託
- NISA
- iDeCo
- その他投資
- 不動産

各資産に設定する項目:

- 現在残高
- 毎月の積立額
- 想定利回り
- 積立開始年月
- 積立終了年月

個別銘柄単位での管理は行わず、ライフプラン上の資産推移を把握するための粒度に留める。

## 8. シミュレーション

最低限、年単位で以下を計算する。

```
年間収支 = 年間収入 - 年間支出
年末資産 = 年初資産 + 年間収支 + 運用損益
```

将来的に以下も考慮する。

- 収入上昇率
- インフレ率
- 投資利回り
- 年金
- 住宅ローン
- 教育費
- 税金 / 社会保険
- 退職金
- 資産取り崩し

ただし、初期バージョンでは計算精度と入力負荷のバランスを重視する。

## 9. プロダクト設計方針

このアプリは「厳密なFP計算ソフト」ではなく、

**一般ユーザーが将来のお金を簡単に把握できること**

を最優先する。

そのため、

- 入力項目を増やしすぎない
- 標準値 / プリセットを活用する
- 後から詳細設定できる
- GUI操作中心
- 数字だけではなくグラフ・タイムラインで理解できる

という方針で設計する。

## 10. 決定事項

### ライフプラン管理

- 1ユーザーは複数のライフプランを作成できる
- ライフプランは複製できる
- 複製したプランを使い、FIRE・進学・住宅購入など条件違いのシナリオを作成できる
- 将来的に複数シナリオを比較できる機能を提供する方向とする
- 初期リリースではライフプランは1アカウントで管理する
- 将来的に夫婦・パートナーで同じライフプランを共同編集できるようにする
- データモデルは将来の共同編集を考慮し、ライフプランにオーナー / メンバー概念を追加できる構造とする

### シミュレーション時間単位

- 内部計算は月単位とする
- メインの可視化・年表表示は年単位を基本とする
- 月額入力（給与、生活費、住宅費など）を内部で月次計算し、年次表示へ集計する
- 必要に応じて将来的に月次詳細ビューを追加できる設計とする

### シミュレーション期間

- 想定寿命の初期値は90歳とする
- ユーザーは想定寿命を変更できる
- 家族メンバーごとに想定寿命を持てる設計とする
- ライフプラン全体の計算終了時点は、原則として対象メンバーのうち最も遅い想定寿命までとする
