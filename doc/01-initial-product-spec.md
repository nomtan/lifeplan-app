# Lifeplan App 初期仕様

最終更新: 2026-09-01

## 1. プロダクト概要

Lifeplan App は、ユーザーが人生のお金の計画をGUIで直感的に把握できるライフプラン管理サービス。

ファイナンシャルプランナーやライフプランナーが作成するような「年表ベースの収支シミュレーション」を、専門知識がなくても個人で作成・更新できることを目指す。

対象プラットフォーム:

- Web
- iOS
- Android

## 2. プロダクトの目的

ユーザーが以下を時系列で整理し、将来の家計・資産状況を把握できるようにする。

- 収入
- 日常生活費
- 住宅関連費
- 子どもの教育費
- 自動車関連費
- 保険
- 税金・社会保険
- 大型支出
- 老後資金
- 資産・預貯金
- 投資資産
- その他のライフイベント

最終的には、「何歳のときに、どの程度のお金が必要で、その時点で資産がどれくらい残っているか」を視覚的に理解できるUIを提供する。

## 3. 基本UX

中心となるUIは「年表 / タイムライン」。

ユーザー本人および家族の年齢・ライフイベント・収入・支出・資産推移を同一時間軸上で確認できるようにする。

想定する主な可視化:

- 年ごとの収入
- 年ごとの支出
- 年ごとの収支
- 金融資産残高
- 家族それぞれの年齢
- 教育イベント
- 住宅イベント
- 大型支出イベント

詳細なUI仕様は今後決定する。

## 4. フロントエンド

### Web

- Framework: Next.js
- UI: HeroUI
- Language: TypeScript

### iOS / Android

- Expo
- React Native
- HeroUI系コンポーネントを可能な範囲で共通化
- Language: TypeScript

Web / Native 間で、ドメインロジック・型・バリデーション・APIクライアント等は可能な限り共有する。

モノレポ構成を基本候補とする。

## 5. バックエンド

Cloudflareを基本基盤とする。

候補:

- Cloudflare Workers: API
- Cloudflare D1: RDB
- Cloudflare R2: ファイル保存が必要になった場合
- Cloudflare KV: 高速参照用データが必要になった場合
- Cloudflare Queues / Cron Triggers: 非同期処理・定期処理が必要になった場合

具体的な利用サービスは要件確定後に決定する。

## 6. 認証

予定するログイン方法:

- Sign in with Apple
- Sign in with Google
- Email address

認証基盤の第一候補:

- Clerk

ClerkはNext.js / Expo双方の公式SDKが存在するため、Web・iOS・Androidを同じ認証基盤で管理する方向。

Expo側のネイティブ認証UIに依存せず、初期実装ではClerk SDKとアプリ独自UIを組み合わせることを基本候補とする。

最終採用は認証仕様確定時に決定する。

## 8. シミュレーション

最低限、年単位で以下を計算する。

```
年間収支 = 年間収入 - 年間支出
年末資産 = 年初資産 + 年間収支 + 運用損益
```

将来的に以下も考慮する。

- 収入上昇率
- インフレ率
- 投資利回り
- 年金
- 住宅ローン
- 教育費
- 税金 / 社会保険
- 退職金
- 資産取り崩し

ただし、初期バージョンでは計算精度と入力負荷のバランスを重視する。

## 9. プロダクト設計方針

このアプリは「厳密なFP計算ソフト」ではなく、

**一般ユーザーが将来のお金を簡単に把握できること**

を最優先する。

そのため、

- 入力項目を増やしすぎない
- 標準値 / プリセットを活用する
- 後から詳細設定できる
- GUI操作中心
- 数字だけではなくグラフ・タイムラインで理解できる

という方針で設計する。

## 10. 決定事項

### ライフプラン管理

- 1ユーザーは複数のライフプランを作成できる
- ライフプランは複製できる
- 複製したプランを使い、FIRE・進学・住宅購入など条件違いのシナリオを作成できる
- 将来的に複数シナリオを比較できる機能を提供する方向とする
- 初期リリースではライフプランは1アカウントで管理する
- 将来的に夫婦・パートナーで同じライフプランを共同編集できるようにする
- データモデルは将来の共同編集を考慮し、ライフプランにオーナー / メンバー概念を追加できる構造とする

### シミュレーション時間単位

- 内部計算は月単位とする
- メインの可視化・年表表示は年単位を基本とする
- 月額入力（給与、生活費、住宅費など）を内部で月次計算し、年次表示へ集計する
- 必要に応じて将来的に月次詳細ビューを追加できる設計とする
